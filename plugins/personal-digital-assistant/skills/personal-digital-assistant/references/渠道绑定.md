# 渠道绑定

## 两种模式

### WorkBuddy 交互模式

使用 WorkBuddy 已安装的连接器。适合用户主动在 WorkBuddy 中查询、管理或确认发送。是否能读取历史消息取决于企业管理员授权和连接器能力。

### 主人控制通道与自动托管

使用 cc-connect 把主人发给机器人的命令通过长连接转交给其支持的本地 Agent。WorkBuddy 当前不在 cc-connect 的 Agent 类型列表中，因此控制通道需要 Codex、Claude Code 等受支持的 CLI；Skill 仍负责统一规则和数据规范。cc-connect 控制通道不自动接管全部同事消息；同事消息托管必须另接平台事件适配器，并调用统一消息策略。

钉钉使用 Stream 长连接；企业微信智能机器人和飞书使用 WebSocket 长连接。三者均不采用定时轮询收消息。

## 钉钉

- 在钉钉开放平台创建应用并开启机器人 Stream 模式。
- 配置 `client_id` 与 `client_secret`。
- 用 `allow_from` 限定可交互员工，先不要使用全员开放。

## 企业微信

- 推荐创建智能机器人并使用 WebSocket 长连接。
- 配置 `bot_id` 与 `bot_secret`，无需公网回调地址。
- 这是机器人/应用身份，不是员工个人账号接管。

## 飞书

- 创建应用并开启机器人能力。
- 订阅 `im.message.receive_v1`，选择 WebSocket 长连接。
- 配置 `app_id` 与 `app_secret`。

## 验收顺序

1. 检查本地依赖和配置文件权限。
2. 平台侧验证应用或机器人状态。
3. 获取主人在平台上的稳定身份 ID，收紧 `allow_from`。
4. 做一条入站测试和一条经确认的出站测试。
5. 验证重复事件不重复发送。
6. 验证人工升级词会转给主人。
7. 验证白名单外消息只记录。
8. 验证关闭 AI 标识后所有发送路径一致。
